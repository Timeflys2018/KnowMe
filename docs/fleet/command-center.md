# 指挥室

指挥室是 Agent Fleet 的**控制塔** —— 不是逐个点开会话，而是在一个视图里签收待办、纵览全局、按需凝练。它由三块组成：置顶的**需处理收件箱**、下面的**全局统揽区**，以及一个可选的 **LLM「凝练」开关**。

![指挥室：置顶「需处理收件箱」+ 全局统揽区 + 顶部凝练开关](/screenshots/fleet-command-center.jpg)

## 需处理收件箱

散落在各处、真正**等你动手**的事，聚合到指挥室顶部的「需处理 N 项」区。它只收**三类互不重叠**的待办，并按轻重给不同的处理方式：

| 待办类型 | 怎么处理 |
|---|---|
| **权限待批**（agent 想执行危险操作，等你批准） | **就地**批准 / 驳回；也可展开**就地回复**（回复是真派活） |
| **任务待验收 / 失败**（任务跑完或出错，等你收口） | **跳去**任务 tab 的抽屉（重上下文，在那里验收） |
| **新访客待审批**（飞书陌生人首次私聊） | **就地**批准 / 拒绝 |

一眼扫到"谁在等我"，多数待办不用离开指挥室就能签掉。

::: warning 就地决策 = 你的显式派活
收件箱里的「批准 / 驳回 / 就地回复」是**你主动做的受控决策**——批准权限、回复 agent 都会真正推进对应会话（走 `sendResume` 派活）。这不同于"自动流程"：指挥室**不会**自己替你发 prompt 或起进程，动作永远由你按下。
:::

## 全局统揽区

收件箱下面，是**所有活跃会话**的一览：

- 以**会话**为单位平铺，带有显式任务（`/task` 建的）的会话会打一个**任务徽标**，标明它在看板里的列状态（待派发 / 进行中 / 待审核 / 已完成）。
- **密度可切换**：紧凑一览表（一行一个会话，扫得快）↔ 叙事卡（信息更全）。

这一区是纯本地投影——直接读会话已有的预览文本、运行态、todos、错误与产出路径，**零延迟、零 token**。

## 可选 LLM「凝练」（默认关）

在纯投影之上，你可以打开顶部的**「凝练」开关**，让一个**你自己配置的模型**把卡片凝练成三段叙事：**完成了什么 / 还剩什么风险 / 证据在哪**。

- **默认关**：不开就是纯本地投影，一个 token 都不烧。
- **懒触发 + 缓存**：只凝练你当前**看得见**的卡片，并按内容 hash 缓存，同样内容不重复调用。
- **单独配置**：凝练用的 provider / model 在设置里**单独指定**，不复用 Wiki 编译的默认模型。

::: tip 凝练是"锦上添花"，不是必需
关着也完全可用——统揽区的状态、徽标、收件箱待办都不依赖 LLM。凝练只是把"一堆卡片"读成"一段人话"，适合会话多、想快速抓重点时打开。
:::
